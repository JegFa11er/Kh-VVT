## Завершённые вехи (Фазы 1 – 5)

- [x] **Фаза 1: База данных компендиумов**: конвертер 17 752 записей из `pf2e-reference`, быстрый поиск и REST API.
- [x] **Фаза 2: Action Intent Pipeline**: валидация ролей GM/Player, сессионный диспетчер `EncounterSession`, рассылка WS-событий боя.
- [x] **Фаза 3: Сетевой стек и раздача**: Vite-прокси, чистый `node:http` production-сервер, WebSocket-клиент.
- [x] **Фаза 4: Интерфейс и Лист персонажа**:
  * HUD, Директории сущностей (Сцены, Актёры, Предметы, Журналы), Компендиум-браузер с Drag-and-Drop.
  * Чат с костями `/r`, загрузкой картинок, всплывающими тостами и облачками (Chat Bubbles) над токенами.
  * Нижний Хотбар макросов (1–0) с переносом бросков из листа.
  * Character Sheet PF2e Remastered: Attribute Builder, формулы КБ/ХП, расчет Bulk, Strikes, спасброски, навыки с ACP, заклинания (подготовленные со слотами и спонтанные), токены с живыми HP-барами.
- [x] **Фаза 5: Физика и Визуальный движок**:
  * 5.1 Коллизии стен (Line Segment Intersection), блокировка движения токенов и snap-back.
  * 5.2 Raycasting-движок видимости (Line of Sight), обрезка света полигонами, поддержка ландшафтных стен (Terrain Walls).
  * 5.3 Туман войны (Fog of War) на накопительной `PIXI.RenderTexture`, сохранение Base64, скрытие чужих токенов.
  * 5.4 GM Vision и раздельный туман по актёрам.
  * 5.6 Интерактивные чат-карточки заклинаний с авто-броском спасбросков выделенными токенами, зум колесиком мыши.
  * 5.7 Динамические слоты черт по уровню, особенности класса, ItemSheetModal, контекстное меню актёров, размер и теги родословной, minRank.
  * 5.8 Внутриигровые React-диалоги вместо `window.confirm`/`window.prompt`, инлайн-ввод текста на холсте, Token HUD (ХП и состояния), дабл-клик по токену, синие временные ХП, слоистый блок КБ, `minRank` из rule elements, тайные броски всех навыков.
  * 5.8.1 Круговые иконки состояний на токене со стадиями (ЛКМ/ПКМ), всплывающий текст изменения ХП, принудительная категория `bonus` для бонусных черт, `minRank` классовых атак/защиты и финальная вёрстка КБ/щита.

## Завершённый этап: Шаг 5.7 — Доработка листа, динамические слоты черт и карточки предметов

- [x] **ПКМ-меню карточек Актёров**: "Настройка владения", "Экспорт данных" (JSON), "Импорт данных" (JSON), "Создать копию", "Удалить".
- [x] **Эргономика левой колонки листа**:
  * КБ и Макс. ХП в виде `readOnly` блоков (без стрелочек ручного ввода).
  * Исправление ширины КБ: блок не сжимает щит, цифра КБ не обрезается.
  * Временные ХП аккуратной строкой под Текущими и Максимальными.
- [x] **Архитектура вкладки «Черты» (Feats Tab)**:
  * Верхний блок: **Особенности класса** (Class Features) — автоматические способности из документа класса (уровень ≤ текущего).
  * Блоки прогрессии со слотами: **Способности родословной**, **Способности класса**, **Способности навыков**, **Общие способности**.
  * Динамические пустые слоты (`Ур. X · Пустой слот`): рассчитываются строго по текущему уровню персонажа. При повышении уровня открываются новые пустые слоты, при понижении — убираются.
  * Drag-and-Drop черт из компендиума в соответствующие слоты с возможностью очистки.
- [x] **Интерактивные карточки предметов (ItemSheetModal)**: клик по названию раскрывает inline-описание, кнопка-карандаш открывает окно с тегами, описанием и правилами.
- [x] **Теги и Размеры (Traits & Size)**: автоматическая установка размера (`med`, `sm` и т.д.) и тегов родословной в данные актёра.
- [x] **Несбрасываемый минимальный ранг навыков (minRank)**.

## Завершённый этап: Шаг 5.8 — Внутриигровые диалоги, Token HUD, КБ и Rule Elements

- [x] **Отказ от браузерных диалогов**: `ConfirmModal` и `PromptModal` на React для удаления актёров, очистки холста, удаления черт из слотов, названий страниц журнала и радиусов света.
- [x] **Текстовый инструмент холста**: HTML-`input` появляется по координатам клика, Enter/потеря фокуса фиксирует `PIXI.Text`, Escape отменяет.
- [x] **Token HUD (ПКМ)**: поле хитов под токеном (`15`, `+10`, `-10` → `room:update-actor`), кнопка «человечек с аурой» с сеткой 30 состояний; HUD следует за камерой и не сбрасывает выделение.
- [x] **Дабл-клик по токену**: открывает лист привязанного актёра с проверкой владения.
- [x] **Временные ХП на токене**: синяя полоса шириной `temp / max` поверх зелёной/жёлтой/красной полосы.
- [x] **Вёрстка КБ**: узкий графический блок, цифра в отдельном абсолютном слое (`z-index: 10`, не обрезается), кнопка «Мод.» вынесена наружу и не перекрывает щит.
- [x] **Rule Elements / minRank**: `ActiveEffectLike` по путям `system.saves|skills|perception|proficiencies…rank` и `system.subfeatures.proficiencies` задают несбрасываемый минимум; UI блокирует ранги ниже него. Поддержаны `ternary`/сравнения/`@actor.level`.
- [x] **Тайные броски**: перечёркнутый глаз есть у всех 16 навыков, знаний и Восприятия; у Стойкости, Реакции и Воли его нет.

## Завершённый этап: Шаг 5.8.1 — Круговые эффекты, Floating Text и фиксы листа

- [x] **Запрет браузерных диалогов**: в `packages/client/src` не осталось `window.confirm`, `window.prompt` или `window.alert`; все подтверждения идут через `ConfirmModal`/`PromptModal`, текст на холсте — через inline `<input type="text">`.
- [x] **Круговые эффекты токена**: иконки состояний рисуются на краю токена, начиная с правого верхнего угла против часовой стрелки; при переполнении круга радиус уменьшается и иконки закручиваются спиралью к центру.
- [x] **Интерактивность эффектов**: ЛКМ увеличивает стадию (`Испуган 1 → 2`), ПКМ уменьшает (`2 → 1`) и удаляет состояние на стадии 1; для нестадийных состояний (например, «Ничком») ЛКМ ничего не делает, ПКМ удаляет.
- [x] **Floating Combat Text**: изменение ХП из Token HUD создаёт `PIXI.Text` в центре токена; зелёный `+N` для лечения, красный `-N` для урона, подъём и затухание за 1.7 с поверх тумана и света.
- [x] **Бонусные способности**: перетаскивание любой черты в секцию «Бонусные способности» принудительно пишет `system.category = "bonus"` и фиксирует её в этом блоке после подготовки актёра.
- [x] **Классовые minRank для Атак и Защиты**: базовые владения класса сохраняются в `details.class.proficiencyFloors` и на каждой подготовке применяются как `minRank` для Simple/Martial/Advanced/Unarmed и Unarmored/Light/Medium/Heavy; UI запрещает выбирать ранг ниже.
- [x] **КБ и Щит**: графический блок КБ сужен, цифра вынесена в абсолютный слой `z-index: 10` и не обрезается, «Мод.» закреплена `top: -10px; right: -20px`, блок Щита придвинут к КБ с зарезервированным зазором.

## Завершённый этап: Шаг 5.9 — Переработка магии, фикс КБ, ограничение ХП и MAP-форматирование

- [x] **Ограничение текущих ХП**: текущие хиты в листе персонажа и Token HUD никогда не превышают максимум (`Math.min(newValue, maxHp)`); поле листа принимает абсолютные значения и дельты (`+20`, `-5`), после коммита показывает уже обрезанное значение.
- [x] **MAP в одну строку**: кнопки атак в вкладке «Бой» показывают `+8`, `+3 (MAP -5)`, `-2 (MAP -10)`; для agile-оружия — `+6 (MAP -4)`, `+2 (MAP -8)`.
- [x] **Компактный КБ**: фоновый блок уменьшен до 50 px, цифра живёт в абсолютном слое `z-index: 10` и свободно выходит за рамку; «Мод.» закреплена сверху справа (`top: -10px; right: -20px`), Щит придвинут вплотную и не перекрывается.
- [x] **Ранги по уровню**: максимальный доступный круг ячеек = `Math.ceil(level / 2)`, максимум 10; в селекте рангов недоступные круги заблокированы.
- [x] **Спонтанные заклинания**: вместо кнопок «+/−» два поля `[Текущие] / [Макс]` и кнопка `↻ Обновить`; «Сотворить» тратит ровно 1 текущую ячейку.
- [x] **Подготовленные заклинания**: в заголовке каждого ранга поле ввода числа слотов; ввод `2` рисует ровно 2 пустые ячейки; в шапке набора появилась кнопка `📖 Подгот.`.
- [x] **Книга подготовки**: новое React-окно `SpellPreparationModal` со списком заклинаний набора; Drag-and-Drop из книги в пустую ячейку ранга заполняет её; «Сотворить» зачёркивает заклинание, корзина очищает ячейку.

## Завершённый этап: Шаги 6.1–6.2 — Профили, Лобби и Матрица владения

- [x] **Постоянные профили пользователей**: `EncounterSession.profiles` (id, имя, роль, цвет, местоимения, `characterId`, дата создания); `session.json.users[]` и `sequences.profile` переживают перезапуск сервера. Профиль создаётся из Лобби через `POST /api/lobby/users`; имя уникально.
- [x] **Лобби до загрузки холста**: `packages/client/src/ui/StartScreen.jsx` рендерится первым, до PixiJS и основного React-интерфейса. Список профилей, выбор, кнопка «Войти», создание игрока/мастера; F5 возвращает в Лобби. WebSocket открывается только после входа, `memberId = profile.id`.
- [x] **Матрица владения Foundry**: `actor.ownership = { default: 0, [userId]: 3 }`; уровни `0 Нет доступа`, `1 Ограниченный`, `2 Наблюдатель`, `3 Владелец`. Модалка `OwnershipModal.jsx` (ПКМ → «Настройка владения», только GM) показывает «Все игроки» и все реальные профили; сохранение идёт через `room:update-actor`.
- [x] **Клиентская проверка прав**: `permissions.js` (`getOwnershipLevel`, `canViewActor`, `canEditActor`). Уровни 0/1 → Toast «Нет доступа» и лист не открывается; уровень 2 → лист с `pf2e-sheet--readonly`, `inert`-контентом и запретом drag-and-drop; уровень 3 или GM → полный доступ. Директория блокирует drag актёров без Owner.
- [x] **Серверная защита**: `EncounterSession#updateActor()` требует Owner (3) или GM; менять `ownership` может только GM; `characterId` больше не даёт прав. GM всегда уровень 3.
- [x] **Тесты**: сервер 77/77 (`tests/ownership.test.js` — матрица, default-row, запрет self-escalation, save/load, HTTP+WS), клиент 78/78 (`tests/permissions.test.js`), ядро 558/558; сборка клиента 806 модулей.

## Завершённый этап: Шаг 6.3 — Настройки сцены, Фокус и Заговоры

- [x] **Модалка настроек сцены**: `packages/client/src/ui/sidebar/SceneConfigModal.jsx`. GM открывает её кнопкой ⚙ на карточке сцены в правой панели. Поля: фоновое изображение (URL или загрузка через `/api/upload`), размер сетки в пикселях (по умолчанию 100, диапазон 20–400), цвет фона вне карты (HEX). Есть предпросмотр изображения.
- [x] **Серверная модель**: `scenes[id].img`, `scenes[id].gridSize`, `scenes[id].backgroundColor`; интент `room:update-scene` доступен только GM, сохраняет настройки в `session.json` и рассылает `room:directories-update`. `room:scene-activated` и `snapshot` передают блок `scene` с настройками.
- [x] **Клиентский холст**: новый `canvas/background-layer.js` рисует фон через `PIXI.Sprite`, цвет вне карты применяется к renderer background, `GridLayer` перестраивается под сохранённый `gridSize`, а количество клеток выводится из размеров изображения. Сетка поверх картинки использует пониженную заливку.
- [x] **Vite dev**: `/uploads` проксируется на Node-сервер, поэтому загруженные фоны и картинки чата открываются и на порту Vite.
- [x] **КБ и Щит**: popover «Расчёт КБ» перенесён в `.pf2e-ac-row`, ширина `max-width: 240px`, правый край не выходит за левую панель. Блок КБ расширен до 64 px; щит стал таким же блоком 64×46 px, значения прочности/хитов сверху, подпись «ЩИТ» снизу.
- [x] **Фокус-поинты**: `system.resources.focus = { value, max, cap: 3, override, known }`. `prepareActorData` автоматически считает максимум по изученным заклинаниям фокусировки без трейта `cantrip` (не более 3); вкладка «Заклинания» показывает глобальные инпуты «Текущие / Максимум» и кнопку «Авто» после ручного оверрайда. Каст фокус-заклинания тратит очко фокуса, а не ячейку.
- [x] **Заговоры (ранг 0)**: убраны поля количества ячеек и слоты подготовки для ранга 0; заголовок показывает «Заговоры · без ячеек, неограниченно». Кнопка «Сотворить» доступна и после каста, ячейки не расходуются ни у подготовленных, ни у спонтанных заклинателей.
- [x] **Тесты**: ядро 558/558; сервер 86/86 (новые тесты настроек сцены: defaults, clamp, persistence, activation/snapshot, GM-only WS broadcast); клиент 80/80 (новые тесты focus pool: cap 3, cantrip exclusion, duplicate names, manual override); сборка клиента 808 модулей.

### Шаг 6.3.1 — Фикс интерфейса Фокус-заклинаний и пула Фокуса

- [x] **Условный пул фокуса**: фиолетовая плашка `.pf2e-focus-pool` рендерится только при наличии набора «Фокусировка» (`isFocusSpellcastingEntry`) или `focus.max > 0`; чистый лист её не показывает.
- [x] **Ранги убраны**: у набора `mode === "focus"` нет селектора круга, кнопки «+ Ранг ячеек» и группировки по кругам; все заклинания идут единым плоским списком, пустой набор показывает drop-зону.
- [x] **Каст из пула**: заклинание 1+ круга в фокус-наборе требует `focus.value > 0`, отправляет чат-карточку и тратит 1 очко через `room:update-actor`; заговор (ранг 0) кастуется бесплатно и бесконечно.
- [x] **Дроп и сохранение**: заклинание из компендиума сохраняется в `actor.items` с `entryId` и `system.location.value` целевого набора, без записи ранга ячейки.
- [x] **Тесты**: клиент 83/83 (новые: определение фокус-набора, стоимость очка по рангу, сохранение `location.value` при дропе), ядро 558/558, сервер 80/80, сборка клиента 808 модулей.
